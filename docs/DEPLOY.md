# Putting the store on Render (step 4)

`render.yaml` in this repository describes everything Render needs (a "Blueprint"). Render reads
it and creates:

| What | Render name | Plan | About |
|---|---|---|---|
| The shop (web service) | `dream-auto-builders` | Standard: 2 GB memory, 1 CPU | $25/month |
| A 10 GB disk on the shop, for product photos and uploaded SEMA files | `data` | | $2.50/month |
| The catalog database (Postgres 16) | `dab-db` | Basic-256mb, 5 GB storage | $6 + $1.50/month |

That's about **$35/month**. The shop needs Standard rather than Starter ($7) because catalog
imports run on it, and the largest file so far (MagnaFlow) uses about 400 MB of memory while
loading. Both can be changed later in the Render dashboard.

## One-time setup (about 10 minutes)

1. In the Render dashboard, click **New** > **Blueprint**.
2. Pick the **Dream-auto-builders** repository. (Render's GitHub access was set to "Only select
   repositories"; this repository is already in that list.)
3. Give the Blueprint a name (for example `dream-auto-builders`). Render lists the database, the
   web service and the disk from `render.yaml`.
4. Render asks for two values. Type them into Render only (never into a chat or email):
   - **ADMIN_PASSWORD**: the password for the admin page, where catalogs are uploaded. Make it strong.
   - **SITE_PASSWORD**: a simple password for the test site. Anyone you give it to can look around.
5. Click **Apply**. Render adds a card to your account if it doesn't have one, creates the
   database, builds the shop and starts it. The first build takes about 5 minutes.
6. Open the shop's web address (shown at the top of the `dream-auto-builders` service, something
   like `https://dream-auto-builders.onrender.com`). You'll see the sign-in page for the test site.

The site is empty at this point: the database has the categories but no parts yet.

## Loading the catalog

1. Go to `<your address>/admin` and sign in with ADMIN_PASSWORD.
2. Under **Add or update a brand**, choose the brand's files from SEMA Data (the zips as
   downloaded, no need to unzip):
   - PIES (required)
   - ACES and the Admark Vehicle Assignment Template (if the brand has them)
   - Digital Assets zip (optional; photos are downloaded from the links in PIES)
3. Leave **Download photos** ticked and click **Upload and import**. Keep the page open until the
   upload finishes (the page reloads and shows the job running). After that you can close it:
   the import keeps running on the server.
4. Do one brand at a time. The catalog part takes a minute or two; photos take longer
   (MagnaFlow: about 7,000 parts, roughly 30 to 60 minutes).

A brand that isn't on the site yet is added automatically, using the brand name in the file
(or the name you type in **Brand name**). Its logo comes from the SEMA logo file, and shows in
**Featured Brands** on the home page, on the Brands page and on the brand's own page.

To update a brand later, upload its newer files the same way. Parts missing from a new full
PIES file are marked discontinued.

## After a deploy or restart

Every push to GitHub's `main` branch redeploys the shop. A deploy restarts it, which stops a job
that is running. The admin page then shows the job as interrupted. The catalog step is all or
nothing (the old catalog stays if it's cut off), and **Download photos** carries on where it
stopped.

## Settings

| Setting | Value on Render |
|---|---|
| `DATABASE_URL` | Filled in by Render from the database |
| `SECRET_KEY` | Generated by Render. Signs shoppers' cookies (cart, garage) |
| `ADMIN_PASSWORD`, `SITE_PASSWORD` | Set by you. Change them on the service's Environment page |
| `SITE_PREVIEW` | `1`: test-site ribbon, hidden from Google. Set to `0` on launch day |
| `COOKIE_SECURE` | `1`: cookies only over HTTPS |
| `DATA_DIR`, `PHOTO_DIR` | On the disk: `/var/data`, `/var/data/photos` |

To open the site to the public at launch: delete `SITE_PASSWORD`, set `SITE_PREVIEW` to `0`, and
add your domain under the service's **Settings > Custom Domains**.

## Growing later

- **Photos**: about 1.3 GB for the first 8,200 parts. At 500,000 parts that's roughly 80 GB, which
  belongs in object storage with a CDN (Cloudflare R2) rather than the disk. The code already
  supports it (`PHOTO_STORAGE=s3`, see `importer/storage.py`).
- **Database**: move to Basic-1gb ($19) when the catalog passes about 50,000 parts or search
  feels slow.
